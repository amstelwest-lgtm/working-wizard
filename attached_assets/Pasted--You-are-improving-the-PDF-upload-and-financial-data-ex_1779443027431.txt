
You are improving the PDF upload and financial data extraction system
for a financial intelligence platform called Milōn.

CONTEXT:
Users (accountants and SME owners) upload PDF financial statements —
bank statements, income statements, balance sheets, management accounts,
or full annual financial statements. The platform extracts specific
financial figures to calculate 31 financial health ratios organised
across four pillars: Profit, Assets, Financing, and Cash.

The current PDF parsing is broken. Replace it entirely with an
AI-powered extraction pipeline as described below.

═══════════════════════════════════════════════════════════════
PART 1 — TECH STACK DECISION
═══════════════════════════════════════════════════════════════

Do NOT use pdf-parse, pdfjs-dist, pdf.js, or any raw text extraction
library as the primary extraction method. These fail on:
- Bank statements where columns are positioned with whitespace
- Scanned/image-based PDFs with no text layer
- Multi-column layouts where text streams incorrectly
- Inconsistent formatting across different SA banks and accounting firms
- Currency formatting variations (R 1,234.56 vs R1 234,56 vs 1,234.56 CR)

USE instead: Claude API with native PDF document support.
Claude reads PDFs as documents — not as extracted text — and understands
semantic meaning of financial line items regardless of formatting, layout,
or whether the PDF is text-based or scanned.

──────────────────────────────────────────────────────────────
STEP 1: PDF to Base64
──────────────────────────────────────────────────────────────

When a PDF is uploaded, convert it to base64 in the browser:

const fileToBase64 = (file) => new Promise((resolve, reject) => {
  const reader = new FileReader();
  reader.onload = () => resolve(reader.result.split(',')[1]);
  reader.onerror = reject;
  reader.readAsDataURL(file);
});

const handleExtractionWithFallback = async (file) => {
 
  // File type check
  if (file.type !== 'application/pdf') {
    return {
      error: 'Please upload a PDF file.',
      fallback: false
    };
  }
 
  // File size check — Claude accepts up to 32MB
  if (file.size > 32 * 1024 * 1024) {
    return {
      error: 'PDF exceeds the 32MB limit. Please compress the file or split it into smaller documents.',
      fallback: false
    };
  }

  // Warn on large files that will be slow
  const estimatedSeconds = Math.ceil(file.size / (1024 * 1024) * 3);
 
  try {
    const base64 = await fileToBase64(file);
    const result = await extractFinancialData(base64, file.name);
    return { success: true, data: result, estimatedSeconds };
  } catch (error) {
    console.error('Extraction error:', error);
    return {
      error: 'Could not automatically extract data from this document. ' +
             'This may be a heavily formatted or encrypted PDF. ' +
             'Please enter the values manually using the form below.',
      fallback: true
    };
  }
};

STEP 4: Multi-document support
──────────────────────────────────────────────────────────────

Support uploading up to 3 PDFs simultaneously. This covers the common
SA SME scenario where income statement, balance sheet, and cash flow
statement are separate documents from different sources.

Build a mergeExtractions function that:
- Takes an array of up to 3 extraction results
- Merges them with later uploads overwriting earlier ones for
  duplicate fields
- Tracks which document each value came from
  (source_document: "document_1" | "document_2" | "document_3")
- Flags any conflicts where two documents provide different values
  for the same field — show these as warnings in the review UI

const mergeExtractions = (extractions) => {
  const merged = { current_period: {}, source_map: {}, conflicts: [] };
 
  extractions.forEach((extraction, index) => {
    const docLabel = `document_${index + 1}`;
   
    Object.entries(extraction.current_period || {}).forEach(([section, values]) => {
      if (!merged.current_period[section]) {
        merged.current_period[section] = {};
      }
     
      Object.entries(values || {}).forEach(([field, value]) => {
        if (value !== null && value !== undefined) {
          const existingValue = merged.current_period[section][field];
         
          if (existingValue !== null &&
              existingValue !== undefined &&
              existingValue !== value) {
            merged.conflicts.push({
              field: `${section}.${field}`,
              value_1: existingValue,
              source_1: merged.source_map[`${section}.${field}`],
              value_2: value,
              source_2: docLabel
            });
          }
         
          merged.current_period[section][field] = value;
          merged.source_map[`${section}.${field}`] = docLabel;
        }
      });
    });
  });
 
  return merged;
};

STEP 5: Normalisation layer
──────────────────────────────────────────────────────────────

CRITICAL: All ratio calculations must run against normalised values,
not raw extracted values. A 6-month management pack next to a 12-month
annual set will produce completely wrong ratios if not normalised first.

Build a normaliseExtraction function that:

const normaliseExtraction = (extraction) => {
  const periodMonths = extraction.document_metadata?.period_months || 12;
  const annualisationFactor = 12 / periodMonths;
 
  // Fields that should be annualised if period is not 12 months
  const flowFields = [
    'revenue', 'cogs', 'gross_profit', 'fixed_costs', 'labor_cost',
    'depreciation', 'amortisation', 'depreciation_amortisation_total',
    'ebitda', 'ebit', 'interest_expense', 'ebt', 'tax', 'net_income',
    'director_remuneration', 'dividends_declared', 'operating_cash_flow',
    'capex', 'dividends_paid'
  ];
 
  // Fields that should NOT be annualised (point-in-time balance sheet items)
  const stockFields = [
    'total_assets', 'fixed_assets', 'current_assets', 'inventory',
    'debtors', 'cash', 'total_liabilities', 'current_liabilities',
    'creditors', 'equity', 'wip'
  ];
 
  const normalised = JSON.parse(JSON.stringify(extraction));
 
  if (periodMonths !== 12) {
    // Annualise flow fields
    flowFields.forEach(field => {
      const value = normalised.current_period?.income_statement?.[field]
                 || normalised.current_period?.cash_flow_statement?.[field];
      if (value !== null && value !== undefined) {
        // Apply annualisation to the correct section
        ['income_statement', 'cash_flow_statement'].forEach(section => {
          if (normalised.current_period?.[section]?.[field] !== undefined) {
            normalised.current_period[section][field] =
              normalised.current_period[section][field] * annualisationFactor;
          }
        });
      }
    });
   
    normalised.normalisation_applied = true;
    normalised.original_period_months = periodMonths;
    normalised.annualisation_factor = annualisationFactor;
  }
 
  return normalised;
};

const parseFinancialNumber = (value) => {
  if (value === null || value === undefined) return null;
  if (typeof value === 'number') return value;
  const str = String(value).replace(/[R$\s]/g, '');
  // Handle comma decimal format
  if (/^\d{1,3}(\.\d{3})*(,\d+)?$/.test(str)) {
    return parseFloat(str.replace(/\./g, '').replace(',', '.'));
  }
  return parseFloat(str.replace(/,/g, ''));
};

    return JSON.parse(rawText);
  } catch {
    const jsonMatch = rawText.match(/\{[\s\S]*\}/);
    if (jsonMatch) return JSON.parse(jsonMatch[0]);
    throw new Error('Could not parse extraction response');
  }
};
